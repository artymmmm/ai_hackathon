# Хакатон ДКБ, второй этап — три кейса по кибербезопасности

Три задания решены **одним конвейером и тремя подключаемыми кейсами**: обезличивание
документов, защита от инъекций в промпт, ревизия кода. Общая часть — загрузка данных, вызов
языковой модели, единый формат вердикта, выгрузка в xlsx и json. Кейс добавляет только свою логику.

Все три датасета обработаны **целиком**, без выборок. Метрики ниже посчитаны по фактически
сданным файлам, а не по образцу и не по оценке.

---

## 3. Что и как решено

### Кейс №1 — обезличивание с сохранением смысла

Два слоя поверх одного текста. **Детекторы** (регулярные выражения плюс проверки формата:
Луна для карт, диапазоны для IP, грамматика идентификаторов) берут форматные сущности.
**Языковая модель** добирает свободнотекстовые — имена, географию, демографию: 20 типов из 55,
которые регулярным выражением не описываются в принципе. Найденное сливается в один список
и заменяется **согласованными псевдонимами**: один человек получает одно и то же вымышленное
имя по всему документу, карта заменяется на карту, проходящую Луна, дата сдвигается на общий
для документа сдвиг — структура и читаемость сохраняются.

Замер вклада слоёв (n=200): только детекторы F1 0.586, только модель F1 0.461,
**вместе 0.809** — слои находят разное.

Дальше **самопроверка**: обезличенный текст повторно прогоняется детекторами, и если что-то
осталось, документ уходит на ручную проверку. Так помечено 2 067 документов из 100 000.

### Кейс №2 — инъекция на входе

**Офлайн-классификатор** (TF-IDF + логистическая регрессия) решает 95.2% потока сам,
с точностью 0.994. Оставшиеся 4.8% — «серая зона», где он не уверен: они уходят в языковую
модель и помечаются **на эскалацию**, как требует задание.

Честная оговорка, которая есть и в отчёте: на полном тесте слой модели дал **+1 верный
документ** из 480 по сравнению с чистым офлайном. Офлайн-слой уже стоит на измеренном потолке
датасета (F1 0.9844), и брать сверху нечего. Ценность серой зоны операционная — она честно
показывает, где система не уверена, — а не метрическая.

### Кейс №3 — ревизия кода

Три независимых детектора на каждом фрагменте, вердикт `vulnerable` ставится по **объединению**:

| слой | что делает | стоимость |
|---|---|---|
| LLM-ревьюер | один вызов на фрагмент: вердикт, CWE, механизм эксплуатации, патч | $8.99 |
| flawfinder | сторонний статический анализатор | 0 |
| сигнатурный триаж | наши регулярки: 7 категорий опасных конструкций | 0 |

Объединение, а не пересечение: слои ошибаются по-разному, и требование согласия обрушивает
результат (Youden J +0.053 против +0.187). Фрагментам, которые нашла **только статика**,
CWE и патч достраиваются отдельным проходом модели — при этом её явно спрашивают, согласна ли
она с анализатором, и **несогласие сохраняется в выгрузке**, а не прячется.

Код из датасета **никогда не компилировался и не исполнялся** — прямое требование задания.
Все проверки, включая проверку предложенных патчей, статические.

## 4. Как это устроено в коде

```
run.py --case 1|2|3          общий запуск
core/                        ядро, одинаковое для трёх кейсов
  llm.py                     ЕДИНСТВЕННАЯ точка контакта с моделью: ретраи, ограничение
                             параллелизма, учёт токенов и стоимости, режим --dry-run без
                             сети и кеш ответов в SQLite по хешу промпта (за счёт него
                             падение прогона стоило времени, а не денег: перезапуск
                             доплачивал только за неотвеченное)
  pipeline.py                стадии load -> prefilter -> route -> llm -> validate -> calibrate
  schema.py                  общий контракт вердикта для всех кейсов
  data.py, export.py         загрузка датасетов, выгрузка в xlsx и json
cases/pii/                   кейс 1: детекторы, слой модели, псевдонимы, самопроверка
cases/guard/                 кейс 2: офлайн-классификатор, серая зона
cases/codereview/            кейс 3: ревьюер, триаж, проверка патчей, объединение слоёв
report/                      отчёты по кейсам и журнал работы
out/bench/                   метрики и сырые вердикты всех прогонов
```

Клиент модели провайдер-агностичный: транспорт OpenAI-совместимый, модель задаётся строкой
в конфиге. Прогон шёл на `deepseek-chat`; замерялись также gpt-5-mini, qwen3-30b и GigaChat —
сравнение в [report/model_benchmark.md](report/model_benchmark.md).

## 5. Как воспроизвести

Двух вещей в репозитории нет намеренно: **датасетов организаторов** (не наши данные) и
**выгрузок** (69 МБ). Что нужно доложить:

| что | откуда | куда положить |
|---|---|---|
| датасеты кейсов 1 и 2 | ссылки из задания, Hugging Face | `case 1/data/`, `case 2/prompt-injection-safety/data/` |
| датасет кейса 3 | приложен к заданию | `case 3/3 кейс_датасет.csv` |
| выгрузки | [релиз v1.0-delivery](../../releases/tag/v1.0-delivery) | `out/` |

Разметка кейса 3, результаты flawfinder и сигнатурного триажа **уже в репозитории**
(`research/case3_recovered_labels_v4.csv`, `cases/codereview/out/*.csv`).

### Пересчёт метрик по сданным файлам

Сети не требует, ключей не требует, считает ровно те числа, что стоят в отчётах.

```bash
# нужны только выгрузка кейса 3 из релиза — датасет для этого не нужен
.venv/bin/python cases/codereview/evaluate_delivered.py out/case3_verdicts.json out/bench/case3_delivered_metrics.json

# нужны выгрузки из релиза + соответствующие датасеты
.venv/bin/python cases/pii/evaluate_delivered.py   out/case1_verdicts.json test out/pii/delivered_metrics_100k.json
.venv/bin/python cases/guard/evaluate_delivered.py out/case2_verdicts.json test out/guard/delivered_metrics_10k.json
.venv/bin/python cases/codereview/length_baseline.py out/case3_verdicts.json out/bench/case3_length_baseline.json
```

### Прогон с нуля

```bash
# конвейер целиком на заглушках: без сети и без ключей, нужны только датасеты
.venv/bin/python run.py --case 1 --sample 20 --split test --dry-run

# боевой прогон (нужен DEEPSEEK_API_KEY в .env)
./full_run.sh
```

Полный прогон трёх кейсов стоил **$22.31** и занял около часа при 64 параллельных запросах.
Повторный прогон у нас обходился бесплатно за счёт локального кеша ответов, но **сам кеш
в репозиторий не попадает** — он содержит ответы модели на данные организаторов. Так что
для постороннего повторный прогон стоит те же деньги.
