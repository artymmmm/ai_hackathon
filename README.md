# Хакатон ДКБ, второй этап

Три кейса по кибербезопасности: обезличивание документов, защита от инъекций в промпт,
ревизия кода. Решены одним конвейером с тремя подключаемыми модулями.

Все три датасета обработаны целиком, без выборок. Числа ниже посчитаны по сданным файлам.

## Результаты

| Кейс | Объём | Качество |
|---|---|---|
| №1 Обезличивание | 100 000 документов | precision 0.930 · recall 0.868 · **F1 0.898** |
| №2 Инъекция на входе | 10 000 запросов | precision 0.982 · recall 0.988 · **F1 0.985** |
| №3 Ревизия кода | 18 864 фрагмента | precision 0.104 · recall 0.382 · **F1 0.164** |

F1 кейса №3 низкий не по ошибке: уязвимых в корпусе 5.6%, и F1 при таком перекосе почти
ничего не измеряет. Разбор — в [отчёте по кейсу 3](report/case3.md).

## Как решено

**Кейс 1.** Регулярные выражения берут форматные данные — телефоны, карты, счета, даты.
Языковая модель добирает то, у чего формата нет: имена, адреса, географию, демографию.
Найденное заменяется согласованными псевдонимами: один человек получает одно вымышленное имя
по всему документу, карта заменяется картой, проходящей Луна, дата сдвигается на общий сдвиг.
Плашки `[УДАЛЕНО]` не используются — документ должен остаться читаемым. В конце обезличенный
текст прогоняется детекторами заново; если что-то осталось, документ уходит человеку.

Слои дополняют друг друга: по отдельности F1 0.586 и 0.461, вместе 0.809.

**Кейс 2.** Классификатор на TF-IDF решает 95% потока сам с точностью 0.994. Остальные 5% —
там, где он не уверен, — идут в языковую модель и помечаются на эскалацию.

Честно: на полном тесте модель дала **один** верный документ сверх классификатора. Офлайн-слой
уже стоит на потолке этого датасета. Серая зона нужна не ради качества, а чтобы показывать,
где система не уверена.

**Кейс 3.** Три независимых детектора на каждый фрагмент — языковая модель, flawfinder и наши
регулярки. Вердикт «уязвим» ставится, если пометил хотя бы один: слои ошибаются по-разному,
и требование их согласия роняет результат втрое.

Код из датасета не компилировался и не исполнялся — ни фрагменты, ни предложенные патчи.

## Устройство

```
run.py --case 1|2|3
core/          ядро: вызов модели, стадии конвейера, общий формат вердикта, выгрузка
cases/pii/     кейс 1
cases/guard/   кейс 2
cases/codereview/  кейс 3
report/        отчёты и журнал работы
out/bench/     метрики всех прогонов
```

Модель задаётся строкой в конфиге, транспорт OpenAI-совместимый. Прогон шёл на `deepseek-chat`,
занял час и стоил $22.31.

## Воспроизведение

Датасетов и выгрузок в репозитории нет: первые не наши, вторые тяжёлые. Датасеты — по ссылкам
из задания, выгрузки — из релиза.

```bash
# метрики кейса 3 — нужна только выгрузка, датасет не требуется
.venv/bin/python cases/codereview/evaluate_delivered.py out/case3_verdicts.json out/bench/case3_delivered_metrics.json

# метрики кейсов 1 и 2 — нужны выгрузки и датасеты
.venv/bin/python cases/pii/evaluate_delivered.py   out/case1_verdicts.json test out/pii/delivered_metrics_100k.json
.venv/bin/python cases/guard/evaluate_delivered.py out/case2_verdicts.json test out/guard/delivered_metrics_10k.json

# прогон с нуля
./full_run.sh
```
