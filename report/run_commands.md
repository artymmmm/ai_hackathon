# Боевой прогон: команды, время, деньги

Всё запускается из корня репозитория. Питон только из `.venv`. Ключи `run.py` подхватывает
из `.env` сам.

## Маршрут

Все три кейса идут на `deepseek-chat` через прямой API `https://api.deepseek.com/v1`
(ключ `DEEPSEEK_API_KEY`) **вне пикового окна**.

Пик — 01:00–04:00 и 06:00–10:00 UTC в будни, то есть 04:00–07:00 и 09:00–13:00 по Москве.
Всё остальное время и выходные целиком идут со скидкой 50%. Скидка подтверждена счётом:
за прогон 28.08 в 10:10 UTC списано $0.026 при расчёте по пиковому тарифу $0.049 — ровно 53%.

В пик прямой API дороже OpenRouter в полтора раза ($0.44 против $0.2574 за миллион входных
токенов), поэтому запускать в пиковом окне смысла нет.

Обе конфигурации, на которых измерены метрики, уже стоят в боевом пути: кейс 3 идёт через
`review_fragments_cert_only`, промпт кейса 1 — с переставленным вниз блоком «Контекст документа».

## Деньги

Смета посчитана по замеренному расходу токенов: 1351 токен запроса и 65 токенов ответа
на документ в кейсе 1, 2388 и 577 на фрагмент в кейсе 3, 45 052 токена на 1000 запросов
в кейсе 2. Тариф вне пика: $0.22 за миллион токенов запроса мимо кеша, $0.007 за миллион
из кеша, $0.55 за миллион токенов ответа. Поверх — коэффициент 1.11 на занижение расчёта.

| Строка | Объём | Вне пика, с кешем | В пик, без кеша |
|---|---|---|---|
| Кейс 1 | 100 000 документов | $12.25 | $71.00 |
| Кейс 3 | 18 864 фрагмента | $9.55 | $33.90 |
| Кейс 3, перепроверка патчей | ~3 500 вызовов | $0.70 | $1.39 |
| Кейс 2 | 10 000 запросов | $0.12 | $0.25 |
| **Итого** | **128 864 записи** | **$22.62** | **$106.54** |

Расчёт занижает списание примерно на 6–11%: два замера дали коэффициенты 1.066 и 1.11.
В смете заложен больший.

**Остаток на 28.08, 13:17 UTC: прямой DeepSeek $0.68, OpenRouter $5.37.** Для полного прогона
счёт DeepSeek надо пополнить примерно на $22–25.

Биллинг DeepSeek приходит с задержкой в несколько часов: сразу после прогона баланс
не меняется, это нормально. Перезамер перестановки промпта 28.08 обошёлся в $0.15 при
расчётных $0.11.

## Время

Замеренная задержка одного вызова: 1.8 с в кейсе 1 (62 вызова за 27.5 с при 4 потоках),
5.8 с в кейсе 3 (621 вызов за 224.5 с при 16 потоках). Пропускная способность растёт не линейно:
восьмикратный рост числа потоков даёт примерно шестикратный рост скорости.

| Кейс | Вызовов | Расчёт при 64 потоках | Закладывать |
|---|---|---|---|
| Кейс 1 | ~100 000 | около 55 минут | до 2 часов |
| Кейс 3 | ~19 500 + 3 500 на перепроверку | около 40 минут | до 1 часа |
| Кейс 2 | ~440 | пара минут | 10 минут |

Троттлинга при 64 потоках не наблюдалось ни у одного провайдера. Кейсы запускать
последовательно: параллельно они делят одну квоту, а выигрыш по времени невелик.

## Проверка перед тратой денег

Сначала вхолостую — сеть не трогается, заглушки детерминированные:

```bash
.venv/bin/python run.py --case 1 --sample 20 --split test --dry-run
.venv/bin/python run.py --case 2 --sample 20 --split test --dry-run
.venv/bin/python run.py --case 3 --sample 20 --dry-run
```

Затем маленький живой прогон на 20 записях, чтобы убедиться, что ключ отвечает, и посмотреть
на реальный расход в строке `llm usage`. Обойдётся в центы.

Метрики кейса 3 в режиме `--dry-run` бессмысленны: генератор заглушек не умеет выдавать вердикт
«уязвим», поэтому все цифры совпадут с базовой линией «всё безопасно». Это ожидаемо.

## Кейс 1 — обезличивание

Полный тестовый сплит, 100 000 документов. Выборка не нужна: с кешем префикса полный прогон
стоит $12.25.

```bash
.venv/bin/python run.py --case 1 --split test \
  --model deepseek-chat \
  --base-url https://api.deepseek.com/v1 --api-key-env DEEPSEEK_API_KEY \
  --max-concurrency 64 --max-tokens 1024 \
  --cache-path out/llm_cache_final_case1.sqlite3 \
  --out-dir out/final
```

Результат: `out/final/case1_verdicts.xlsx` и `.json`.

Метрики по выборке считаются отдельно и денег не стоят, если ответы уже в кеше:

```bash
set -a && . ./.env && set +a && .venv/bin/python cases/pii/evaluate.py \
  --n 200 --split test --ablation \
  --model deepseek-chat --base-url https://api.deepseek.com/v1 \
  --api-key-env DEEPSEEK_API_KEY --max-concurrency 16
```

## Кейс 2 — защита от инъекций

Полный тест, 10 000 запросов.

```bash
.venv/bin/python run.py --case 2 --split test \
  --model deepseek-chat \
  --base-url https://api.deepseek.com/v1 --api-key-env DEEPSEEK_API_KEY \
  --max-concurrency 64 \
  --cache-path out/llm_cache_final_case2.sqlite3 \
  --out-dir out/final
```

Модель здесь почти не влияет на исход, поэтому есть бесплатный вариант без передачи запросов
за периметр:

```bash
.venv/bin/python run.py --case 2 --split test \
  --model GigaChat-2-Max --backend gigachat --api-key-env GIGACHAT_AUTH_KEY \
  --max-concurrency 1 --out-dir out/final
```

## Кейс 3 — ревизия кода

Корпус целиком, 18 864 фрагмента. **`--max-tokens 2048` обязателен**: на 1024 ответы
обрезаются, на 2048 обрезается 2.4% и уходит в повторный запрос.

```bash
.venv/bin/python run.py --case 3 \
  --model deepseek-chat \
  --base-url https://api.deepseek.com/v1 --api-key-env DEEPSEEK_API_KEY \
  --max-concurrency 64 --max-tokens 2048 \
  --cache-path out/llm_cache_final_case3.sqlite3 \
  --out-dir out/final
```

Стадия проверки делает дополнительный вызов на каждый вердикт «уязвим» с непустым патчем.
Это 18.5% фрагментов, около 3 500 вызовов, они учтены в смете отдельной строкой. Отключать
не нужно — это и есть независимая перепроверка.

Метрики против восстановленной разметки считаются по готовым вердиктам и денег не стоят:

```bash
.venv/bin/python cases/codereview/evaluate.py --verdicts out/final/case3_verdicts.json
```

## Если прогон прервался

Кеш ответов в SQLite хранит всё по хешу запроса, модели и параметров. Повторный запуск той же
команды с тем же `--cache-path` не платит второй раз за уже полученные ответы, а добирает
недостающее. Прерывать безопасно. Для финальных прогонов у каждого кейса свой файл кеша.

Важно: кеш привязан к тексту промпта. Любая правка промпта обнуляет попадания и прогон
оплачивается заново.

## Контроль расхода

```bash
set -a && . ./.env && set +a
curl -s https://api.deepseek.com/user/balance -H "Authorization: Bearer $DEEPSEEK_API_KEY"
curl -s https://openrouter.ai/api/v1/credits -H "Authorization: Bearer $OPENROUTER_API_KEY"
```

Расход текущего прогона печатается в конце в строке `llm usage`: число вызовов, попадания
в локальный кеш, токены запроса и ответа, попадания в кеш префикса на стороне провайдера.
